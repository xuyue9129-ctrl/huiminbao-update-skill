# 惠民保官方资料更新

目标：其他Agent不依赖原会话，也能从用户指定工作区恢复任务，取得当年官方依据并安全维护既有工作簿。**Skill本身不授予微信操作、账号访问、联网发布或其他外部写入权限。**

所有脚本路径相对于本skill目录。工具调用中的路径使用绝对路径；命令示例中的相对路径仅为展示，执行前解析。Windows PowerShell 5.1不用`&&`或Bash heredoc，中文PS脚本保存UTF-8 BOM。

## 0. 开工先读与范围

1. 读取工作区和父级`AGENTS.md`、用户最新要求、`latest_progress.json`；仅按任务读取研究文件，不遍历聊天/微信账号目录。
2. 确认目标产品/地区、目标年度、已有行更新还是新增年度行、官方来源范围、颜色规则、是否允许后台微信导航。缺少阻断信息用当前环境的询问工具确认；不能从旧文件中的日期推定今天。
3. 建立TODO。先读[恢复与检查点](references/recovery.md)，再运行`workflow.py preflight`和`inspect --workbook ...`。
4. 核对进度记录的最新文件是否存在、SHA256是否相符、表头/产品是否吻合。若记录被外部修改或哈希不符，停写并重新建立基准。不要仅选修改时间最新文件。
5. 新建独立批次目录：`workflow.py init --workbook <绝对路径> --run-dir <新目录> --year <年度>`。该命令拒绝复用已有目录，保存基准哈希和结构摘要，不复制大型证据。
6. **默认不跑历史批次构建器**：它们可能硬编码日期、行号、基准及输出名。先阅读、确认输入输出，再在新批次参数化适配；不得覆盖旧基准。

## 1. 找资料：官方身份先于产品参数

完整规则见[证据规范](references/evidence.md)，执行微信前必须读[公众号与小程序](references/wechat.md)。

优先顺序：

1. 已记录的官方永久链接、当前官方入口；
2. 产品官方公众号当年发布、产品说明书、投保/理赔须知、责任长图和目录；
3. 官方小程序公开产品详情、投保须知、条款、服务/承保信息；
4. 公众号文章明确内链出的投保H5/说明书/理赔页；
5. 医保局/政府官网、官方公众号、明确针对本产品本年度的保险公司官网公告。

先用当前Agent已有的网页抓取、网页搜索工具及专用连接器；指定平台无工具时先检查可连接服务。公众号正文不可读再使用获授权的本地微信公开页面。检索摘要/文章标题/第三方转载只作线索，不能支撑填值。`mp.weixin.qq.com`域名本身不证明账号官方。H5第三方技术域名须保留来自官方文章的内链证据链。

## 2. 公众号/小程序调取

- 只操作用户已登录的独立研究窗口。首次使用`control.py windows`重取窗口，不沿用HWND、坐标或旧截图。
- `inspect → read/find/capture → 一次定向操作 → 再inspect/read/capture`，逐步确认产品、账号、年度、页面类型和内容确实变化。
- 核验公众号认证主体、账号ID及简介与产品关系，记录公开身份；标题和简介不能替代当年责任正文。
- 公众号读全文及相关保障图，按图原始尺寸分段留证；小程序沿当前可见入口进入产品详情/须知，UIA不可读则用窗口截图，不能把黑图或旧图当已读。
- `#小程序://...`不是通用HTTP API，不能凭分享码编造URL、appid或页面路径。不调用未知私有接口、不读进程内存/账号数据库。
- 禁止发消息、分享给联系人、支付、生成投保订单、签署授权、提交个人信息或接受昵称头像授权。需要新授权时先问用户。遇登录、验证码或访问限制由用户处理，不绕过。
- 导航命令自动启用前台拦截器（见wechat.md），让用户继续使用其他软件。它会向微信进程加载拦截DLL，首次在某台电脑使用前须取得用户同意；不同意则只读取/截图。
- 命令报告`user_foreground_disturbed`、用户正在使用微信、并发争用、连续内容无变化时，停止该类导航并记缺口。不全局键鼠、不置顶窗口；拦截器只把新出现的微信窗口放到底层和屏幕边缘。

## 3. 产品判定与逐字段决策

1. 先证明产品身份和目标年度。新增行须官方命名目标年度或明确保障覆盖目标全年；跨年但未覆盖全年不能自动算新年度。用户点名例外单独登记，不能推广到其他产品。
2. 旧年度只作格式/系列身份参考。只有当年官方明确“保持不变”且引用范围可对应时，才允许据原文沿用。
3. 每个产品一份`decisions/<稳定产品ID>.json`，参考[虚构示例](examples/decision.json)。保存账号核验、年度证据、资料文件、引文、图片页位、冲突、未取得项。
4. 状态分`confirm`、`set`、`withdraw`、`not_found`。`not_found`不自动清空；`withdraw`须明确原值、撤回理由及既有证据复查情况。只因本批材料没重复提到，不能抹掉此前有效依据。
5. 引文不能推导不出的细节一律不填：出席发布会≠指导/承保；名单首位≠主承；平台域名≠健康管理TPA；可参保≠所有既往症都赔；快赔≠出院同步结算；无明文免赔≠0。
6. 一个产品完成后立即保存并`validate-evidence`，再处理下一个。校验通过只证明结构/安全要求，不代替人工核验原文。

## 4. 更新Excel

必须先读[工作簿维护](references/workbook.md)。

- 使用现有产品身份字段定位行，记录`产品/地区/版本/保障起止/当前行号/基准哈希`。行号不是永久ID。
- 保留原工作簿样式、公式、名称、链接、批注和非目标内容。复杂工作簿优先以zip+XML仅改必要部件，正式文件不经COM直接覆盖保存。
- 现有单元格可用`workflow.py apply --workbook ... --plan ... --output ... --log ...`；它要求基准SHA、单元格旧payload、每项理由与证据引用，拒绝覆盖输入及已有输出/日志。输入协议见工作簿指南。
- 插行必须另做受控迁移：复制正确样式模板，公式平移，更新跨表引用、合并/表/名称/验证范围、来源行号和跳转，重新编号；不能仅调用`insert_rows`就交付。
- 2026旧行错误修正标黄、新修改标红是本项目惯例，不是所有任务通则。当次用户另定则遵从；记录本批使用规则。
- 保单年按同一产品系列真实期次核验全系列，不根据年份差盲加、不顺带修无证据字段；K分组连续编号；BY无字典映射保留公式并显示空白，不扩编字典猜分类。

## 5. 必过验证

1. `workflow.py verify --workbook ...`重新打开zip及XML、解析工作簿、查公式/错误缓存/外部链接并记录SHA。
2. 与基准逐部件/逐单元格比对：变化只在批准范围，所有变化有日志，原值校验无冲突，所有公式变更有记录，源文件哈希未变。`apply`自动完成其支持范围内的检查；复杂迁移还需自定义独立验证。
3. 直接验证用户给定规则：新增行年度与保障期、目标行红字、旧更正黄底、K连续、BY公式及无映射为空；不能用平均通过率代替逐项门槛。
4. 检查来源表产品总览、详情块、内部跳转和官方外链。不能把所有未知域名直接删掉，须核验是否官方内链；也不能因域名已在旧白名单就跳过年度/主体核验。
5. Excel可用则对**基准副本和候选副本**分别运行`recalculate.py`，不更新外部链接、不启用宏。缓存从Excel保存的临时文件读取，不把COM负整数CVErr当数值写入。对比新增错误，解释预期错误和遗留错误。
6. 若回嵌重算缓存：仅对公式表达式未变且对应坐标/工作簿已核验的单元格回嵌；`t=e`写真实错误字符串，空白缓存与空字符串区分。依赖上游修改的未改公式也需检查缓存。回嵌后重新跑全部依赖该文件的验证和哈希，不引用回嵌前的哈希。
7. Excel不可用时，不伪造重算结果，标记“未执行Excel引擎重算”，不得宣称公式结果全部验证。

## 6. 断点和交付

- 单一主写者维护`latest_progress.json`；按[恢复规范](references/recovery.md)原子写入。取实际当前日期，区分资料截止日与操作日期。
- 记录最终文件路径、SHA、基准、修改/验证报告、产品状态和未解决项。筛查完成≠正文齐全≠参数齐全，分开统计；缺失计数未知就写null。
- 停止仅由本批启动且已不需要的后台进程，记录未采纳原始资料；不得终止用户Excel/微信进程或清理用户文件。
- 中文交付可点击Excel路径、实际完成范围、关键验证、未读正文及遗留公式问题。用户没要求，不向GitHub/微信等平台发布任何研究文件。

## 辅助脚本说明

`workflow.py --help`列出`preflight/init/inspect/validate-evidence/apply/verify/scan-package`。`recalculate.py --help`说明Excel临时副本重算。`scripts/wechat/control.py --help`列出窗口操作。

依赖清单在本目录`requirements.txt`。通用脚本建议Python3.10+；当前环境缺依赖时先报告并按工作区策略取得安装许可，再使用`python -m pip install -r <本目录绝对路径>/requirements.txt`，不擅自改变全局环境。验证范围见[验证记录](references/validation.md)。

本skill是可执行的工作流与安全辅助工具，不是无人值守微信爬虫，不会突破客户端兼容性或平台访问控制。前台拦截已在实测的公众号/搜一搜操作上做到零扰动，未覆盖的页面仍以每次报告为准。没有足够依据或工具时，留空、记阻塞、交付已验证部分。
