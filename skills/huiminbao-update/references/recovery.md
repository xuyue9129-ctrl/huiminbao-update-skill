# 断点续做、并发与失败恢复

## 一批一目录

```text
工作区/
  latest_progress.json
  runs/<操作日期-唯一批次>/
    run.json
    evidence/<稳定产品ID>/
    decisions/<稳定产品ID>.json
    plans/
    reports/
    candidate.xlsx
```

目录不是强制要求用户搬动旧资料。已有`work_年度`结构可继续用，但每批分离，不能覆盖上次产物。`init`写入基准路径、SHA、实际操作时间、目标年和队列状态。保存检索到的“未读”线索时明确标记，不写成“已核”。

## 检查点

每完成一个产品，写出独立决策文件；每次修改候选文件后写修改日志；每次验证后记录验证所针对的SHA。仅最终验证通过后更新`latest_workbook`，失败保留上一已交付版本。

推荐进度：

```json
{
  "as_of": "实际操作日期",
  "materials_as_of": "官方材料截止日或null",
  "latest_workbook": "最终文件绝对路径",
  "sha256": "最终已验证哈希",
  "base_workbook": "不可变基准",
  "counts": {"screened": 0, "updated": 0, "not_added": 0, "body_missing": null},
  "pending": [],
  "validation": {"structural": "报告路径", "excel": "报告路径或未执行"},
  "next_steps": []
}
```

原子写：同目录写临时JSON、读回校验、`os.replace`替换。不要把密码/token写进临时文件。每次写进度前读最新版本、比哈希；外部变动时合并或停止，不能覆盖其他Agent更新。

## 单写者原则

- 同一工作簿和进度仅一名Agent写入。
- 多Agent只有用户/项目明确要求时才并行；研究任务按产品隔离，研究者只提交决策，不写主工作簿。
- 微信独立窗口也只能一名操作员；单命令互斥锁不能防住不同脚本之间整段任务交错。
- 不共享历史HWND，不把基准坐标当插行后坐标。

## 常见失败

| 失败 | 恢复 |
| --- | --- |
| 公众号标题可见、正文验证码 | 保存标题线索，记body_missing，不猜价格、不新增参数 |
| 搜索页仍是上个产品 | 重新读账号/标题/结果，内容未变则停，不采错产品 |
| H5域名不在旧白名单 | 核对官方父文章内链，不按域名外观删来源 |
| Excel COM挂起 | 报未完成，只停止本批创建且可明确识别的Excel实例，不终止所有EXCEL.EXE |
| openpyxl read_only随机单格访问很慢 | 采用一次顺序遍历或非只读加载；大表XML直读，不能反复从头扫描 |
| 来源表没有dimension元素 | 合法可选元素，按sheetData最大行列计算，不当作文件损坏 |
| XML部件叫sheet22但仅8张表 | 解析workbook关系，不按部件编号统计表数 |
| CVErr被写成负整数 | 从Excel已保存副本重提真实缓存，回嵌后全部重验 |
| 最终文件被外部更改 | 比对SHA，重读日志与文件，不引用过期验证 |
| 磁盘告警 | 停止大规模采集/写入，只清自己确认不需要的临时产物，不删用户/缓存目录 |
| Git作者未配置 | 不覆盖身份或借机器人身份冒充；请用户配置，或使用已有授权的远程发布渠道默认身份 |

## 交付措辞

“已筛查178款”不等于“178款当年正文均已阅读”；“更新76行”不等于“全部字段完整”；“没有新增非预期错误”不等于“全表零错误”。分别报告事实、缺口和未执行验证。
