# 公众号、小程序与官方H5：实际操作手册

## 授权与能力探测

只针对用户授权的公开产品资料。先观察已有独立研究窗口，不能把微信主聊天窗口作为输入目标。用户未允许客户端导航时，仅用官方公开网页与已有证据。不要为了完成采集，擅自点击登录、头像昵称、医保信息、投保声明或支付授权。

优先当前环境已提供的专用工具；没有微信专用工具时，可使用本skill的Windows辅助脚本。它通过UI Automation、窗口定向PostMessage和PrintWindow实现有限读取/导航。**不需要手机/虚拟机，不等于任意版本都能用。**

```powershell
$python = (Get-Command python -ErrorAction Stop).Source
$skill = (Resolve-Path '.factory/skills/huiminbao-update').Path
$wx = Join-Path $skill 'scripts/wechat/control.py'
& $python -X utf8 $wx windows
```

如`python`是商店占位程序，使用已有Python绝对路径或`py -3`。不要把其他电脑用户名和运行时路径硬编码进流程。

## 必须坚持的状态机

`观察 → 识别页面 → 选择唯一控件 → 一次操作 → 等待应用完成 → 重新观察 → 保存检查点`。

1. `windows`列出微信窗口元数据，不读私人聊天内容。选独立搜一搜/文章/小程序窗口的当前HWND。
2. `inspect --hwnd H`核对进程、标题、窗口尺寸、前台/最小化状态、子窗口。`H`是本次返回值，不是示例可直接运行的字面量。
3. `read`保存UIA文档；先确认是搜索页、账号主页、文章还是小程序，不能只因文本很多就算正文。
4. `find`获取当前控件、类型、支持模式和矩形。匹配多项须明确`--index`，索引从0开始。
5. 优先`setvalue/invoke/scrollinto/scroll`；只有截图和控件定位明确时才用`click`。不支持的控件记录阻塞，不盲发连续输入。
6. 每次动作后再`inspect`及`read/capture`确认；辅助工具短时前台检查可能漏掉延迟激活，后续观察仍必须做。

```powershell
# 将 $h 替换为本次观察到的整数窗口号，$evidence 是本批证据目录绝对路径
& $python -X utf8 $wx inspect --hwnd $h
& $python -X utf8 $wx read --hwnd $h --out (Join-Path $evidence 'before.txt')
& $python -X utf8 $wx find --hwnd $h --name '*' --type Edit
# 仅在刚确认的公开搜一搜输入框上替换文字
& $python -X utf8 $wx setvalue --hwnd $h --name '*' --type Edit --index 0 --value '示例市民保2028'
& $python -X utf8 $wx find --hwnd $h --name '搜索' --type Button --exact
& $python -X utf8 $wx invoke --hwnd $h --name '搜索' --type Button --exact
& $python -X utf8 $wx inspect --hwnd $h
& $python -X utf8 $wx read --hwnd $h --out (Join-Path $evidence 'search-result.txt')
```

搜索按钮不存在时，可以在**刚验证的搜索输入框**使用单次`key --key enter`，不能在聊天窗口盲按Enter。`chars`不替代Ctrl+A，替换输入用`setvalue`。截图坐标按当前像素与客户区/窗口坐标计算，不沿用固定缩放倍率；实际子窗口必须经inspect验证。

## 公众号路径

1. 从已观察到的搜一搜页面搜索产品全名，可加目标年度；同名多账号核验认证主体、公开账号ID、官方简介、医保局/保险公司指向关系。
2. 保存`profile.txt`及关键身份截图。认证主体为运营/经纪公司不自动否定官方，但必须有与产品的明确关系。账号昵称相似不足以确认。
3. 在账号文章列表筛选：正式上线/开放参保、产品详情/方案、投保须知、理赔须知、重要说明、药品/医院/药店目录、个账/一站式答疑。
4. 先读产品详情和须知，再看发布稿与问答；宣传总保额不能代替分项限额。新增内容须确认正文确实属于本年度。
5. 展开“余下N篇”、懒加载和翻页一次一步；前后内容哈希/标题/账号未变则视为操作未生效，不能无限重试。
6. 全文按产品归档：URL、标题、账号、发布日期、读取时间、正文及图片顺序。UIA正文遗漏长图时必须读图；药品种数可数清目录，但不可凭图片占位符推断。

## 小程序路径

1. 优先官方公众号菜单/正文可见的小程序卡片或微信里已打开的官方入口。用观察到的控件进入，不猜小程序名与appid关系。
2. 确认主体/简介/产品名称/年度，保存首页及产品详情标题。
3. 只读：保障详情、投保须知、保险条款、责任免除、既往症约定、药械目录、理赔流程、承保与服务机构。
4. 画布无UIA文字时用`capture`，视实际需要定向滚动并截连续区段。每段保留重叠区域和序号，避免漏行。当前截图为黑屏、停渲染、无变化时标记不可读。
5. 进入投保页若要求勾选协议、领取授权、输入身份证/手机号或生成订单，立即停下。产品研究不等于允许提交这些动作。
6. `#小程序://...`仅是分享描述，不能直接传给FetchUrl，更不能猜私有接口。取不到公开信息就记录页面/字段缺失。

## 文章内链H5

1. 从已验证官方文章保存锚点文字与目标URL，建立`官方账号 → 文章 → 产品H5`链。
2. 提取链接时先删除会话参数，再用FetchUrl。禁止传出`exportkey/pass_ticket/uin/wxtoken/access_token`等凭据，也不要把完整原始链接打印到日志。
3. 官方内链可以是技术/经纪公司域名，不能仅用`.gov.cn`判定；反过来，普通第三方域名不能靠“页面看起来像投保页”认定官方。
4. 仅GET公开说明页，不猜创建订单、支付、授权确认URL，不调用表单提交API。跳转到验证码或登录则停。
5. H5的年度、主体、保障期间与正文再核对，保留冲突。入口日期和正式发布日不同，区分“开放投保日”“发布日”，不要机械二选一。

## 必须停止的情况

| 现象 | 处理 |
| --- | --- |
| 前台窗口是目标或动作后自行激活 | 停止输入，记录动作/页面；不置顶、不强行切回、不换全局键鼠 |
| 要求绝不打断用户，但新页面导航会激活 | 只处理已读内容，交付兼容性阻塞，不承诺全自动 |
| 验证码、登录或昵称头像/医保授权 | 请用户处理或明确授权，不绕过、不代填 |
| 同窗口由其他Agent操作 | 单一操作员串行，窗口消息互斥只能覆盖单次调用，不保证整个任务互斥 |
| 标题有2028但正文没取得 | 记为“当年线索，正文未读”，不新增参数 |
| 旧结果残留/账号不匹配 | 重读核验，不从错误产品抽取 |

历史上UIA Invoke、滚动和搜索Enter都曾触发微信自行激活；窗口消息点击有后台成功个例，也有失败。包内辅助不带进程注入、原生钩子或焦点恢复模块，不能保证导航不抢焦点。
