# 证据、年度和决策协议

## 一条值的最小证据

每个set/confirm包括列字母、值、原值（set/withdraw）、理由、逐字引文和source_id。来源记录包括：

- kind：`official_account`、`official_miniprogram`、`official_h5`、`government`、`insurer_official`、`official_profile`；
- 官方身份判定及理由，标题、URL（可无）、实际发布日期（未知null）、访问时间、本地证据相对路径；
- 非政府域名H5的官方父文章source_id及父文内的链接原文；
- 图片证据写文件名、分段/页位和相关文字，不只写“见图”。

`official=true`是研究人员作出的可审计判定，不是程序根据域名自动生成的结论。校验器不联网证明身份，也不保证引文真实。

## 年度门槛

产品JSON中单独记录`target_year`、`year_basis`和`product_id`。`year_basis`包括：

- `kind=named_year`：官方原文明确目标年度/版本；
- `kind=full_calendar_coverage`：原文保障起止覆盖目标全年，填写ISO日期；
- `kind=user_exception`：用户明确给出的特定产品例外，保存授权原文，不适用于同城其他产品。

上市于上一年很正常。保障跨年但只覆盖部分目标年，不自动生成目标年新品；版本期数不等于公历年。保单年CC须沿同一系列核验，不能直接`目标年-首年+1`，停办、重命名或一年多期另查。

## 值与缺失的四种状态

| action | 意义 | 可否直接修改 |
| --- | --- | --- |
| confirm | 已有值有当年官方证据 | 通常不改值，补来源 |
| set | 官方足以支持新/更完整值 | 主写者复核后写入 |
| withdraw | 明确错误、非官方来源或原依据不成立 | 核验原值和既有依据后清空；保留理由 |
| not_found | 这次未取得所需证据 | 不等于不存在、不等于不赔、不等于删旧值 |

未获得当年依据时不复制去年参数。曾有证据的旧值不能仅因新采材料未重复披露就撤回；先查已有来源，区分“本批未出现”与“原依据不可靠”。

## 禁止推断

- 承保名单按顺序列出，不代表第一家主承；未披露份额填“未知”，不是均分。
- 官员出席发布会，不代表该部门指导/支持；“监管”与“指导”保留角色差异。
- 公司承载H5或认证公众号，不代表提供全部健康管理服务；BX区分经纪、运营、技术和TPA角色。
- 不限年龄/健康状况投保，不代表所有既往症责任同赔。
- “免申即赔”不必然是出院时同步结算。
- 未写免赔额，不等于免赔0；合计保障额度不等于单项限额。
- 责任描述含多个子项时，不把其中一个子项的既往症规则扩到整项。

## 冲突与来源优先

不存在“只要新稿就覆盖一切”的绝对顺序。区分保险条款/特别约定、正式方案、投保须知、理赔须知、宣传问答的适用对象和生效时间。若官方存在日期、异地扣减或版本待遇冲突：

1. 保存两处原文、发布日期、版本/人群；
2. 查正式勘误或当年解释；
3. 能明确适用关系则按关系写明；无法解决就留空或并列准确注明冲突，不擅自修“明显笔误”；
4. 把取值理由及未解决冲突写入来源表和进度。

## 安全留证

只保存公开产品信息，先对URL会话参数脱敏，再落盘或交给外部工具。不能把账号文件、进程内存、完整登录链接、聊天记录或投保人信息当证据。截图若含私人内容，先调整到纯公开产品页面再采集；不要发布带私人信息的截图。

资料按`evidence/<product_id>/`保存。文件可以为空白URL（小程序/简介无永久URL），但必须有本地文件与公开入口描述。`validate-evidence`检查路径不逃出run-dir、文件存在、来源身份标记/理由及引用完整性。所有研究产物留在实际工作目录，不复制到公开skill仓库。
